# 可复用工作流

岗位与搜索词 → 列表采集 → 指定 UID 补读 → 标准审阅 → 联系前预检 → 完整批次审阅 → 授权发送 → 同一会话回读。

1. `detail data/search.json --uid <UID> --out data/detail.json`：读取确定人选；UID 不是姓名或行号。
2. 复制并完善 `policy.draft.json`，经岗位负责人确认后另存 `policy.confirmed.json`。
3. `screen` 只提取线索。审阅者需在每个必须项填写原文证据、判断、理由，并核对团队联系历史。
4. `preflight` 检查关联岗位、人选身份、额度和自动求简历开关，随后关闭弹窗。
5. `prepare` 校验名单、要求、原文、预检和文案。`approval` 输出待审阅内容与文件指纹。
6. 获得当次明确授权后，在对应文件记录批准人与批准状态，再次生成最终指纹。
7. `send <batch.json> --confirm <最终指纹> --out data/result.json` 会发送并消耗账号权益；没有自动重试。
8. 到同一人选会话核对正文与时间。`recover` 的列表不能替代聊天送达核验，也不证明附件已收到。

审批、事件、运行结果保存在 data/，属于私有资料，不提交 Git。
目前公开核心未提供完整聊天回读自动化、自动翻页全覆盖和附件下载闭环。
