# 全栈招聘数据看板

[展示入口](demo.html) · [输入与输出](GUIDE.md) · [结构化资料](case.json) · [流程图](flow.mmd)

## 为什么做

当时使用的飞书页面难以直接看清总体进展，笔试占用面试轮次，真实流程、转化漏斗和面试官进展需要重新整理。

## 解决什么问题

把分散的阶段、人选、渠道和面试记录整理到同一视图，支持按时间与面试官核对。

## 原来怎么工作

打开飞书不同报表和人选记录，手动拼出总体漏斗；笔试占用面试轮次后，还要重新确认各轮含义并汇总面试官反馈。

## 现在我做什么

定义实际招聘流程、阶段映射、目标和统计口径，复核异常数字，判断需要怎样调整寻访和推动面试反馈。

## 现在 AI 做什么

协助改造开源页面，编写数据读取、汇总、筛选与图表代码，实现阶段明细和面试官进展展示。

## 实际完成范围

已有全栈招聘看板原版界面、数据接入、周期筛选、阶段明细、目标完成度和面试官进展。首版落地可追溯到 2026-07-23 的仓库提交，不将后续修改计入首版周期。公开版使用 2026-09-21 的历史脱敏快照；招聘人数不作为工具提效或录用贡献。

## 怎样复用

先为各指标写明来源、统计区间和去重方法，再接入新岗位；阶段人数不能直接当作转化率。

## 贡献与来源

基于 CuiSheng-TAO/algo2-recruit-board 改造。我关注岗位适配、指标口径、数据刷新和使用要求，AI 协助代码实现。
